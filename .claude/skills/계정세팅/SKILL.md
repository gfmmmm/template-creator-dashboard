# 계정세팅

한 번 돌리면 `계정/<핸들>/`이 채워지고 `/릴스대본기획`을 쓸 수 있게 된다. 다시 돌리면 갱신이다(기존 문서를 읽고 더하되, 사용자가 직접 고친 줄은 남긴다).
말투: 존댓말, 호칭 없음. 사용자에게 명령어·파일 편집을 시키지 않는다.

## 원칙 (전 단계)

- 모든 주장에 출처 번호(M-### 본인 게시물, R-### 발굴). 출처를 붙일 수 없는 문장은 문서에 넣지 않는다
- 숫자(빈도·길이·비율)는 `lib/measure.py`가 낸 것만 쓴다. Claude가 어림한 숫자를 쓰지 않는다
- 원문 인용은 대본·캡션 그대로. 다듬거나 지어내지 않는다. 대본은 음성 자동 전사라 오인식이 있을 수 있으니 캡션과 교차해 확인된 구절만 인용한다
- 문서 양식은 `계정/_template/`의 절 구조와 "채우는 법" 지시를 그대로 따른다. 절을 빼거나 새로 만들지 않는다
- 재료가 적으면 적다고 쓴다("대표대본 7건 기준"). 늘려 쓰지 않는다

## 0. 준비

1. 데이터 모드 확인 — `bash .claude/skills/릴스대본기획/lib/fetch.sh mode` (supabase / json / manual)
2. 핸들 확인 — `계정/`에 `_template` 말고 폴더가 있으면 그것. 없으면 "인스타그램 아이디(@ 뒤)를 알려주세요" → `계정/_template/`를 `계정/<핸들>/`로 복사
3. 사용자에게 한 줄: "본인 릴스를 재료로 문서 5개를 만들게요. 10분쯤 걸리고, 중간에 세 번 확인을 부탁드릴 거예요."

## 1. 대표대본 모으기

기준선: 게시물이 40건 이상이면 조회 상위 20건, 그 미만이면 상위 절반(최소 5건). 사용자가 다른 기준을 말하면 그것.

- supabase: `bash .claude/skills/릴스대본기획/lib/fetch.sh my_top <기준 조회수>`
- json: `.env`의 `DASHBOARD_DIR`에서 `data/posts.json`의 `my.posts[]`를 `views` 내림차순. 대본은 `transcript`, 코칭이 있으면 `data/analysis.json`의 `coaching[shortcode]`에서 `video_analysis`(첫 3초·자막 스타일 재료)와 `analysis`(안티패턴 B절 재료)
- manual: 사용자에게 부탁 — "잘 된 릴스 10~20개의 주소(URL)를 한 줄에 하나씩 주세요. 대본추출 도구가 있으면 제가 음성을 글로 뽑고, 없으면 캡션과 영상에서 하는 말을 받아 적어 붙여 주세요(릴스당 조회수 / 캡션 / 대본)." 첫 3초는 릴스마다 "첫 3초에 화면에 뭐가 보이나요?" 한 줄씩 묻는다(모르면 비움)

파일 만들기: `계정/<핸들>/대표대본/_index.md`의 "파일 형식" 그대로 `M-###_조회수_캡션첫줄20자.md`. cardNo가 데이터에 있으면 그 번호, 없으면 조회순으로 M-001부터. 표(`_index.md`)를 채운다 — 기둥은 데이터(analysis.pillars 또는 settings.overrides)가 있으면 그것, 없으면 비움. 수익유형은 캡션의 공구·광고 표식(#공구·#공동구매·#특가·#마감·#광고·#협찬·#내돈내산)으로 공구/광고/일반.

검증: 파일 수 = 기준선 건수, 각 파일에 `## 대본`·`## 캡션` 절이 있다. 대본이 빈 파일은 `## 대본` 절을 비워 두고, 머리 인용줄에 `> 대본 없음(무음 또는 미추출)`을 적는다 — 절 안에 쓰면 measure.py가 그 표시를 문장·어미로 센다.

## 2. 재기

`python3 .claude/skills/계정세팅/lib/measure.py 계정/<핸들>/대표대본 > /tmp/measure.json` 후 읽는다. 이 JSON의 숫자만 문서에 쓴다.
발굴 레퍼런스가 있으면(supabase·json) 훅 재료로 상위 30건의 첫 두 문장도 모은다 — supabase: `fetch.sh refs ""`(키워드 없이 조회순), json: `discoveries.json` items 조회순 30건의 transcript 첫 두 문장과 `videoAnalysis.초반3초훅`.

## 3. 문서 5개 쓰기 (이 순서로, 하나 쓰고 다음)

### 프로필.md
- 정체성: 대시보드 `settings.brief`(json) 또는 `fetch.sh ctx`의 브리프를 원문 인용. manual이면 사용자에게 "이 채널을 한 문단으로 소개하면?"을 받아 그대로
- 정체성이 대본에서 발화된 구간: 대표대본 중 채널 정체를 말하는 문장 1~2개 (M-###)
- 타겟: brief에서 뽑거나 사용자에게 묻는다
- 점검 기준: 템플릿 문구 유지 + 이 계정 고유 가치 메시지가 있으면 한 줄(대본 근거). 단 `[타겟]` 자리는 이 계정의 타겟 문구로 바꾼다
- 기둥 표: 데이터가 있으면 기둥별 건수·중앙 배율(기둥 중앙 조회 ÷ 전체 중앙 조회)·2배 이상 건수·대박률을 계산해 채우고 해석 두세 문장. 없으면 표를 비우고 "기둥 분류 없음 — 대시보드에서 '기둥 정해서 분류해줘' 뒤 갱신"
- 규모: 게시물 수·평균 조회·대표대본 기준선·최고 조회(M-###)·평균 문장 길이(measure)
- 수익 구조: 캡션 공구 표식 비율(measure.caption.commerce_marked), 대표대본 중 공구 비율, 실제 판매 채널 문구 인용

### DNA.md
- 1절: measure.first_person·calls 빈도 + 원문 예 각 1~2개(M-###). 대본과 캡션에서 호칭이 다르면 둘 다
- 2절: measure.endings_top15 중 상위 10을 표로. 1위 어미가 2위의 2배 이상이면 "이 계정의 서명"으로 적고, 한 대본에 몇 번 나오는지(파일별로 세어) 분량 규칙을 쓴다 — 연속 문단 끝 어미를 같게 두지 않는다는 규칙은 템플릿 문구 유지
- 3절: measure.words_top40에서 살림·행동 / 지시어·연결어 / 감정·평가 / 관계 어휘로 나눠 표. 각 행에 원문 한 구절(M-###). 빈도 2 이하는 넣지 않는다
- 4절: avg_sentence_len, 첫 두 문장 길이 대 해설 구간 길이(per_file.first_two 대비 본문), 상황극·질문-자답·조건절-처방 중 실제로 있는 것만 원문 예와 함께
- 5절: 조회 상위 4건의 시작(first_two)·중간·끝(last) 원문 → 공통점 두세 문장
- 6절: per_file.last를 유형별로 묶어(안내로 닫기 / 실행 지시 / 농담·자조 / 요청) 원문 예. forbidden의 저장·팔로우·댓글 빈도를 반드시 적는다
- 7절: measure.caption 표 + sample_first_lines 5개 원문
- 8절: forbidden 표 전체. 빈도 0은 "쓰지 않는다", 1~2는 "가끔", 그 이상은 원문 자리 예시

### 형식.md
- 대표대본을 구조가 같은 것끼리 묶는다. 묶음 기준은 첫 문장의 종류(고백·대사·실험·상황·조건절·음원·자막 진행·문제 제시)와 중간의 전개(검증·대사·근거·항목·소절·단계)와 마무리(안내·지시·농담). 한 파일은 한 형식에만
- 2건 이상인 묶음만 F번호. 1건짜리는 문서 끝 "## 사례 (형식 미성립)" 절에 M-###만 나열
- 각 형식: 구조(0~3초/~15초/~40초/마무리 — 대본 문장 순서에서, 추정 초 금지), 해당 대표대본과 조회, 중앙 조회, 대본 길이(per_file.chars_no_space 최소~최대, 발화 중심인지 자막 중심인지), 궁합 훅(4번째 문서에서 매긴 H번호 — 훅.md를 먼저 쓴 뒤 채운다), 촬영 난이도(가족 목소리·소품이 대본에 보이면), 원문 예 2~4개
- 중앙 조회 요약 표를 맨 위에

### 훅.md
- 본인 첫 두 문장(per_file.first_two)과 발굴 상위 30건 첫 두 문장을 같은 여는 방식끼리 묶는다. 예시 이름: 손해·후회 고백 / 대사 난입 / 반전 정체 공개 / 눈으로 먼저 보여주는 대비 / 조건절 지목 / 상식 뒤집기·근거 인용 / 음원·리듬 오프닝 — 이 이름을 그대로 쓰지 말고, 이 계정 재료에 실제로 있는 묶음만 이름 붙인다. 최대 7개
- 각 훅: 공식·작동 원리·본인 예(M-###, 조회)·발굴 예(R-###, @소스, 조회) 원문·궁합 형식
- "유형에 넣지 않은 것": 정보 예고형("~알려드릴게요", "~N개")은 발굴에 많아도 본인 forbidden 빈도가 0이면 안티패턴으로 분류
- 발굴 재료가 없으면(manual) 발굴 예 자리에 "본인 예만"이라고 쓰고, 본인 예 1건짜리 훅은 만들지 않는다

### 안티패턴.md
- A절: 템플릿 4줄 유지 + 사용자에게 묻는다(3단계 검토에서)
- B절: 코칭 데이터가 있으면(analysis.coaching 또는 my_top의 코칭) 개선점·이탈요인 문장을 모아 같은 종류끼리 묶고, 그룹마다 코칭 원문 1~3개(M-###)와 해당 M-### 목록, "대신 이렇게" 한 줄(잘된 본인 대본 인용). 코칭이 없으면 B절에 "코칭 데이터 없음 — 대시보드에서 '내 릴스 코칭해줘' 뒤 갱신" 한 줄만
- C절: 비워 둔다(형식 안내만)

### 공구광고.md
- 대표대본 중 수익유형 공구·광고가 2건 이상일 때만 채운다: 3단 배치 표에 원문, 구매 안내 위치 실측(대사에 안내가 든 건수와 위치, 가격·기간이 대사에 든 건수), 캡션 표식 위치, 공구 선례 표(형식별), 상위권 공구·일반 중앙 조회 비교
- 1건 이하면 문서 머리에 "공구 선례 없음 — 공구·광고 모드에서는 선례 없음으로 안내" 한 줄만 두고 표는 비운다

## 4. 사용자 검토 (하나씩, 답을 받고 다음)

1. `대표대본/_index.md` 표를 보여주고: "이 중에 '나답지 않다' 싶은 릴스가 있으면 번호를 말해주세요. 그 파일은 이름 앞에 `제외_`를 붙여 다음부터 안 읽어요." → 표시한 뒤 measure를 다시 돌려 DNA 2절·8절 숫자를 갱신
2. DNA.md 8절 "쓰지 않는 것"을 보여주고: "여기에 더할 말이 있나요? 내가 절대 안 쓰는 표현이요."
3. 안티패턴.md A절을 보여주고: "하지 말라고 못 박을 것이 있나요?"

## 5. 마무리 보고

한 화면으로: 만든 파일 수, 대표대본 N건 기준, 서명 어미와 빈도, 형식 N개·훅 N개, 비워 둔 곳과 이유(예: 기둥 분류 없음·코칭 없음·공구 선례 없음), 그리고 "이제 `/릴스대본기획`이라고 하면 이 문서로 기획을 시작해요."

## 다시 돌릴 때 ("프로필 다시 만들어줘", 대표대본이 늘었을 때)

- 기존 문서를 먼저 읽는다. 사용자가 직접 고친 줄(A절, DNA 8절 추가, C절)은 그대로 둔다
- measure를 다시 돌려 숫자를 교체하고, 새 대표대본이 있으면 형식·훅에 인용을 덧붙인다(조회가 낮은 인용을 밀어낸다)
- 무엇이 바뀌었는지 한 줄 보고

## 하지 않는 것

- 출처 없는 문장, 어림한 숫자, 다듬은 인용
- 재료가 적은데 문서를 채우기 위해 일반론을 쓰는 것 — 빈 칸은 "재료 없음"이 맞다
- `.claude/` 안의 양식·패턴 문서 수정
