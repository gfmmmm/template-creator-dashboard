# 릴스대본기획

저장소 루트: 현재 작업 폴더(cwd)에서 시작해 위로 올라가며 처음 만나는, `계정/` 폴더나 `.env`가 있는 폴더. `계정/`·`.env`·`기획/`은 전부 거기 기준이다. SKILL.md 자신의 경로로 루트를 정하지 않는다 — 전역 설치본이면 남의 폴더를 가리킨다. 루트를 못 찾으면 기획을 시작하지 말고 "이 도구의 폴더에서 열어주세요"라고 안내한다.
계정 폴더: 저장소 루트의 `계정/<인스타 핸들>/` — 이 폴더가 진실의 원천. `계정/` 안에 `_template` 말고 폴더가 하나면 그것을 쓰고, 둘 이상이면 시작 질문 전에 어느 계정인지 먼저 묻는다. 처음이면 `/계정세팅` 스킬이 `계정/_template/`를 복제해 채운다. 계정 폴더가 `_template`뿐이면 기획을 시작하지 않고 "먼저 세팅이 필요해요 — '구축 가이드대로 진행해줘'라고 해주세요"라고 안내한다. 스킬 본체(`.claude/`)는 특정 계정을 몰라야 한다 — 템플릿 업데이트 때 통째로 교체되기 때문이다.
데이터: 세 가지 모드 중 하나로 읽는다. 어느 모드인지는 저장소 루트의 `.env`로 판단한다.
- supabase 모드 — `.env`에 `SUPABASE_URL`이 있으면 `bash .claude/skills/릴스대본기획/lib/fetch.sh …`. 레시피는 `lib/queries.md`
- json 모드 — `.env`에 `DASHBOARD_DIR`만 있으면 fetch.sh가 그 폴더의 `data/*.json`을 직접 읽는다. 명령은 supabase 모드와 똑같다(ctx·pillars·card·my_top·refs). 데이터 파일을 직접 파싱하지 않는다 — fetch.sh만 쓴다
- 통합 번들 — 이 스킬이 크리에이터 대시보드 폴더 안에 들어 있으면(같은 폴더에 `data/posts.json`) `.env`에 아무것도 없어도 fetch.sh가 json 모드로 그 데이터를 읽는다
- 수동 모드 — `.env`가 없으면 데이터 조회를 건너뛴다. 레퍼런스는 사용자가 붙인 대본·캡션·"첫 3초에 보이는 것" 한 줄이고, 기둥 미달 규칙은 적용하지 않는다. 시작 질문 Q1에 "대시보드가 없으면 참고 릴스의 대본과 캡션을 붙여 주세요"를 덧붙인다
fetch.sh가 ❌를 내면 거기서 멈추지 않는다 — `.env`를 다시 보고 json 또는 수동 모드로 이어간다.
말투: 존댓말. 로봇 용어("터진 문법", "바이럴 메커니즘") 대신 사람 기획자의 말. 사용자를 부르는 호칭("대표님", "OO님")은 쓰지 않는다 — 팀 누구나 같은 화면을 본다.

## 0. 시작 질문 (답 오기 전 아무것도 하지 않는다)
스킬이 불리면 첫 응답은 아래 질문 세 개뿐이다. 인사말, 데이터 조회, 계정 분석, 기둥 현황, "제가 본 것" 같은 앞머리를 붙이지 않는다. fetch.sh 는 답을 받은 뒤 1단계에서 처음 실행한다. 사용자가 이미 답을 일부 준 경우(예: "R-459로 공구 대본") 그 항목은 빼고 나머지만 묻는다. 셋 다 왔으면 묻지 않고 바로 1단계로.

아래 블록을 그대로 출력한다. 질문은 소제목(`##`)으로 크게, 보조 설명은 그 아래 일반 줄로. 질문 사이는 가로줄(`---`)로 끊는다(빈 줄은 화면에서 하나로 합쳐져 구분이 안 된다).

```
## Q1. 이번에 참고할 레퍼런스를 공유해주세요!

대시보드에 있는 레퍼런스 카드 번호(R-###)를 주시거나,
주제를 한 줄로 설명해주시거나,
직접 써보신 초안이 있으면 그대로 붙여주세요.
셋 중 아무거나 괜찮아요.

---

## Q2. 이번 콘텐츠는 어떤 유형인가요?

오가닉 콘텐츠 / 공구 / 광고 중 하나요.
공구나 광고면 제품명, 꼭 넣을 소구점 2~3개, 필수 문구(가격·기간 등)도 같이 적어주세요.

---

## Q3. 이번 콘텐츠를 어떤 느낌으로 기획해보면 좋을지 간단히 남겨주세요.

생각하신 느낌에 더욱 맞게 기획해드릴게요.
```

답을 읽는 규칙: 초안 문장은 손대지 않는다. "오가닉"은 일반 모드다. 필수 문구는 기본이 캡션이고, 대사에 꼭 넣어야 하는 문구가 따로 있으면 그것만 대사에. 느낌 답이 "알아서"거나 비어 있으면 레퍼런스 장치에 맞춰 스킬이 정한다. 촬영 조건(가족 동원 가능 여부)은 묻지 않고, 훅 후보를 낼 때 가족이 필요한 안에는 "가족 출연" 한 마디를 붙여 팀이 거르게 한다. (질문 문구 2026-08-30 확정)

출력은 두 턴이다. 첫 턴은 "후킹 3가지 추천" — 출력형식.md 첫 턴 규격 그대로: A안·B안·C안을 차별화 축으로 이름 지은 소제목(`##`)으로, 안 사이는 가로줄(`---`), 훅은 자막 → 첫 장면 → 다음 컷(대사가 있으면 대사 줄)을 이름표 붙은 글머리표로 한 줄씩, 그 아래 전개 두세 문장(순서가 넷 이상이면 화살표 한 줄로 따로), 마지막에 추천 안과 두 문장 이유. 한 문장에 정보 하나, 45자 안팎 — 술술 읽혀야 한다(2026-08-30 확정). 여기서 멈추고 팀이 고른다. 둘째 턴에 고른 안으로 대본·촬영을 쓴다. 팀이 "웃긴 걸로"처럼 느낌을 말하면 그 느낌으로 3개를 다시 낸다. "바로 써줘"가 붙으면 후킹 3가지와 추천 안의 대본을 한 번에 낸다. (2026-08-30 확정) 출력은 사람 기획자의 메모처럼 — 형식·훅·카드 번호, 느낌 태그, 본인 영상 인용, 글자수 검산, 준비물, 점검표는 안에서만 돌리고 밖으로 내지 않는다(출력형식.md).

## 1. 재료 로드 (항상 전부, 압축하지 않는다)
- 계정 폴더의 `프로필.md · DNA.md · 형식.md · 훅.md · 안티패턴.md`, 공구·광고면 `공구광고.md` 도
- 계정 폴더의 `대표대본/` 의 모든 파일 원문 (`제외_` 로 시작하는 파일은 읽지 않는다)
- `patterns/릴스기획5단계.md · AI티검사.md · 출력형식.md`
- `fetch.sh ctx`, `fetch.sh pillars`
- R 번호: `fetch.sh card R-###` 각각. 자유 주제: 주제어 2~3개로 `fetch.sh refs "…"` 를 나눠 불러 조회 상위 15건을 키워드 밀도로 재정렬해 최대 7건을 레퍼런스 후보로. refs 결과에는 `[첫 3초]`·`[후킹]`·`[주제]`·`[점수]` 가 붙어 나오니 그걸로 후보를 고르고, 최종 채택한 카드만 `fetch.sh card R-###` 로 전문을 다시 받는다. 대본은 음성 자동 전사라 오인식이 있을 수 있으니 캡션과 교차해서 읽는다.

## 2. 훅 후보 3개
훅 후보 하나는 형식(형식.md) × 훅 유형(훅.md) × 레퍼런스 카드 1건의 조합에서 나온 첫 3초다. 조합은 안에서 정하고, 밖으로는 유형 대제목(차별화 축) · 상단 자막 · 첫 장면 · 다음 컷 · 대사 줄 · 전개 한 문단만 낸다(출력형식.md 첫 턴). 세 훅은 형식이 서로 달라야 하고, 유형 대제목은 서로 다른 축이어야 한다 — 하나는 레퍼런스에 충실한 안, 나머지는 무엇을 더하거나 바꾸는지가 이름에 보이게.
각 안의 "왜 될 것인가"는 카드에서 「인용」한다. 인용 없는 확신은 쓰지 않는다. 이번 달 미달 기둥이 있으면 한 안은 그 기둥으로 잡는다. 단 공구·광고 모드에서 그 기둥에 공구 선례(형식.md 해당 형식에 공구 대표대본)가 없으면 이 규칙은 건너뛴다.
재료가 카드 1건뿐이면 세 안이 같은 카드를 써도 된다. 대신 형식은 서로 달라야 하고, 자유 주제일 때는 refs 후보 중 서로 다른 카드를 안마다 배정한다.

## 3. 선택된 안 완성 (출력형식.md 그대로)
- 훅은 짓지 않는다. 레퍼런스 카드의 첫 3초 구조를 「인용」해 이 계정 언어로 옮긴 것만 훅이다
- 대본은 DNA.md 의 어미·표현으로. 대표대본에서 실제 쓴 표현 3개 이상을 재사용한다. 어느 건에서 왔는지는 4단계 점검용이고 출력하지 않는다
- 영상 길이는 어떤 형식이든 30~60초. 대본 글자수는 형식.md 실측 범위를 따르되(공백 제외), 발화가 적은 형식은 자막 시퀀스 글자수로 재고 촬영메모의 장면 시간 합이 30초 이상이어야 한다. 문단 하나가 장면 하나
- 촬영 표: 장면 / 초 / 화면과 자막. 위에 띄우는 자료 화면(제품 사진·비교 표·캡처)은 같은 칸에 "위에 띄우기:"로
- 공구·광고: 공구광고.md 의 3단 배치. 대사의 구매 안내는 마지막 한 문장까지만(제품 핵심 한 줄 + 제품명 + 채널·시점), 또는 대사에 없이 캡션 전담. 가격·기간 등 필수 문구는 캡션 초안에 글자 그대로. 공구·광고 모드에서는 캡션 초안이 필수 산출물

## 5. 선택·다듬기·저장
- 팀이 고른 안을 피드백대로 수정("훅 더 세게", "공구 버전으로", "R-118 문법 섞어봐"). 팀이 직접 쓴 문장은 그대로 둔다 — 살 붙이거나 지어내지 않는다
- "저장" → `기획/YYYY-MM-DD_제목.md` (선택된 안만, 머리에 재료·모드)
- "캡션도" → DNA.md 의 캡션 구조 절대로 초안을 써서 같은 파일 끝에 추가

## 성장 동작
- "이건 하지 마" / "이거 금지" → 계정 폴더의 `안티패턴.md` C절에 추가 (무엇 · 왜 · 대신 어떻게)
- "이 훅 추가해" → `훅.md` 마지막 H번호 다음으로 추가 (공식 · 작동 원리 · 예 · 궁합 형식)
- "이 말투 쓰자" / "이 표현 좋다" → `DNA.md` 해당 절에 추가
- "대표대본 갱신" → 조회 기준선(기본: 상위 20건, 또는 평균의 2배) 이상 릴스 중 대표대본 폴더에 없는 건을 추가하고 `_index.md` 갱신. 재료는 모드별로 — supabase: `fetch.sh my_top <기준선>` / json: `posts.json`의 `my.posts[]` 조회순(대본은 `transcript`, 코칭이 있으면 `analysis.json`의 `coaching`) / 수동: 사용자에게 릴스 주소나 대본·캡션을 받는다. 파일명은 `M-###_조회수_캡션첫줄20자.md`, 본문은 머리 메타(업로드 · 기둥 · 수익유형 · 링크) + STT 주의줄 다음에 4절(`## 대본 (음성 전사 원문)` / `## 캡션` / `## 첫 3초 (시각분석)` / `## 자막 스타일`). 쓰기 전에 대표대본 폴더의 기존 파일 하나를 열어 그 형식을 그대로 복제한다
- 문서를 고칠 땐 한 번에 한 사람만 (드라이브가 충돌 사본을 만든다). 고친 뒤 "안티패턴.md 갱신" 처럼 무엇을 바꿨는지 한 줄 보고
